# SonicWeb-Bingo

忘年会用の3x3自治体ビンゴアプリ。Firebase(Firestore)でリアルタイムに同期する、親機(進行役)・子機(参加者)構成のWebアプリです。

## 画面URL

| 画面 | URL | 用途 |
|---|---|---|
| 親機(進行役・投影用) | `index.html?role=master` | 抽選・クイズの進行、結果発表 |
| 子機(参加者) | `index.html?role=player` | ビンゴカードの表示・クイズ回答 |
| 幹事用セットアップ | `setup.html` | 自治体リスト・クイズ内容の編集 |

親機URLに `&debug=1` を付けると(例: `index.html?role=master&debug=1`)、本番では隠れている開発者向けボタンが表示されます。

- `index.html?role=master` … 本番用。参加者に見せる画面。
- `index.html?role=master&debug=1` … 動作確認用。「🏆 最終結果を発表」「🔄 ゲームをリセット」ボタンが追加で表示される。

## 当日の使い方(進行役)

1. 親機URL(`?role=master`)をプロジェクター等で開く
2. 「次を引く！」でルーレット演出の後、自治体が1つ抽選される(結果は子機にリアルタイム反映)
3. 「クイズを出題する！」でクイズを出題 → 参加者が✊✌️✋で回答 → 「回答受付を終了し判定する」で判定
   - 正解者がいれば、その中から抽選で1人が当選し「ボーナス」として好きな自治体マスを開けられる
4. 自治体をすべて抽選し終えると、**自動で**「ビンゴ達成順位」「クイズ正解数ランキング」が親機画面に表示される
   - 手動で今すぐ見たい/リセットしたい場合は `&debug=1` を付けたURLを使う

## 参加者(子機)の使い方

1. 子機URL(`?role=player`)を開く
2. ニックネームを入力して「設定」(2〜15文字、一度設定すると変更不可)
3. 表示されたビンゴカードのマスは、抽選された自治体をタップすると印がつく(まだ出ていない自治体はタップしても印がつかない)
4. クイズ出題中は✊✌️✋のボタンで回答する

## 幹事用セットアップページ(`setup.html`)

来年以降、担当者が変わってもコードを触らずに自治体リストとクイズを更新できるようにするためのページです。

- 初回アクセス時は好きなパスワードを決めて入力するだけでログインでき、そのパスワードが以後の合言葉になる
- 自治体リスト(1行1つ、9個以上)とクイズ(質問文・選択肢3つ・正解)をフォームで編集できる
- 保存すると Firestore に内容が書き込まれ、以降 `index.html` を開いた参加者・進行役全員に反映される
- パスワードは簡易的なものです(誤操作防止レベル)。本格的な認証ではないため、URLとパスワードの扱いには注意してください

設定を保存していない場合、アプリは `script.js` 内にハードコードされたデフォルトの自治体リスト・クイズ内容(前回大会の内容)を使用します。

## 主な機能

- **抽選ルーレット演出**: 「次を引く！」を押すと1.5秒ほど候補がランダム表示された後に結果が確定
- **ビンゴ達成順位**: 各参加者が最初にビンゴした時点で達成順を記録
- **クイズ正解数ランキング**: クイズ正解者全員の累計正解数を記録
- **自動結果発表**: 自治体をすべて抽選し終えると、親機画面に自動でランキングが表示される
- **カードの保持**: ビンゴカードとマーク状態は端末ごとに保存され、ニックネーム設定やページの再読み込みをしてもリセットされない(進行役がゲームをリセットしたときだけ新しいカードになる)
- **ゆるキャラ画像(サンプル)**: `script.js`内の`prefectureImages`に自治体名と画像パスを登録すると、親機の「現在の抽選結果」にその画像が表示される。現状は`images/`フォルダにオリジナルの汎用サンプル画像が4体分(札幌市・横浜市・鎌倉市・つくば市)入っているのみで、実際のご当地キャラクター画像への差し替えは別途用意が必要(著作権上、実在のキャラクター画像は同梱していません)
- **デバッグ用コンソール関数**(F12で開発者ツールを開いて実行):
  - `debugForceDraw('〇〇市')` … 指定した自治体を強制的に抽選結果に追加
  - `ResetGame()` … 「🔄 ゲームをリセット」ボタンと同じ処理を実行

## ファイル構成

```
index.html   … 親機・子機の画面本体
script.js    … ゲームロジック一式
style.css    … 全体のスタイル
setup.html   … 幹事用セットアップ画面
setup.js     … セットアップ画面のロジック
images/      … サンプルのマスコット画像(SVG)
```

## Firestoreのデータ構成(プロジェクト: `bonenkaibingo`)

| コレクション/ドキュメント | 内容 |
|---|---|
| `bingo/gameState` | 抽選履歴・クイズ出題中フラグなど、ゲーム全体の進行状態 |
| `quizAnswers/{userId}` | クイズ出題中の各参加者の回答(判定後に削除される) |
| `bingoWinners/{userId}` | ビンゴを達成した参加者と達成順 |
| `quizStats/{userId}` | クイズの累計正解数 |
| `config/gameConfig` | setup.htmlで保存した自治体リスト・クイズ内容・セットアップパスワード |

「🔄 ゲームをリセット」を実行すると、`bingo/gameState`・`quizAnswers`・`bingoWinners`・`quizStats` がすべて消去されます(`config/gameConfig`は消えません)。

## 引継ぎ手順(次年度の担当者へ)

このアプリはコードを直接触らなくても、次の2つさえ伝われば運用を引き継げます。

1. **`setup.html`のURLとパスワード**
   - URL: `https://solg-bingo.github.io/setup.html`
   - パスワードは今年の担当者が「保存」を一度でも実行した時点のものが合言葉になっています。次の担当者に口頭やメモで伝えてください。
   - まだ一度も保存していない場合はパスワード未設定なので、次の担当者が初めて開いたときに好きなパスワードを決めて使い始められます。
2. **当日の運用URL(親機・子機)**
   - 親機: `https://solg-bingo.github.io/?role=master`(プロジェクター等に投影)
   - 子機: `https://solg-bingo.github.io/?role=player`(参加者に共有、QRコードにしておくと便利)

### 事前準備(大会の1〜2週間前を目安に)

1. `setup.html`を開き、パスワードでログイン
2. 自治体リストを今年の内容に更新(9個以上、1行1つ)
3. クイズを今年のクイズに更新(質問文・選択肢3つ・正解)。既存のクイズは「✕ 削除」、新規は「＋ クイズを追加」、順番の入れ替えは「↑」「↓」、全部作り直したい場合は各セクションの「空にする」ボタンが使える
4. 「この内容で保存する」を押して保存
5. 親機URL・子機URLで実際に開いて内容が反映されているか確認(README冒頭の「画面URL」を参照)

### GitHubアカウント・コードの引継ぎについて

`setup.html`だけで自治体リスト・クイズの更新は完結するため、次の担当者に**GitHubアカウントやgitの使い方を教える必要は基本的にありません**。

ただし、演出やランキングの仕組み自体を変更したい(コードを修正したい)場合は、GitHubリポジトリ(`https://github.com/solg-bingo/solg-bingo.github.io`)への書き込み権限が必要です。その場合は以下も合わせて引き継いでください。

- GitHubリポジトリへのアクセス権(Organizationのメンバー権限など)
- Firebaseプロジェクト(`bonenkaibingo`)の管理コンソールへのアクセス権(通常の運用では不要。抽選データなどを直接確認・削除したい場合のみ必要)

## GitHubへのpush(認証)

`git push`時のGitHubログインは、鮱名のAppleでログインする。

## 注意点

- FirebaseのAPIキーは`index.html`/`setup.html`内に平文で埋め込まれていますが、これはクライアント用の公開キーであり一般的な仕様です。実際のアクセス制御はFirebase側のFirestoreセキュリティルールで行う必要がありますが、本リポジトリにはルール設定は含まれていません。身内利用が前提の簡易的な構成です。
- `setup.html`のパスワードは誤操作防止程度の簡易的なものです。URLとパスワードを知っている人は誰でも自治体リスト・クイズ内容を書き換えられます。
